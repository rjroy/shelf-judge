## Phase 1 implementation record

- Advanced the SQLite schema from v5 to v6. Existing published judgments migrate in place; new staging, single-batch ownership, and publication-state tables are separate. Existing judgments are not copied into generations.
- Added cache-level primitives: `reserveRunBatch(progress)`, `checkpointStagedPair({ judgments, progress })`, `lookupForRun(runId, key)`, `stagedSnapshot(runId)`, `getRunBatch()`, `sealRunBatch(progress)`, `promoteRunBatch({ runId, expectedStagingRevision, eligibleJudgments, progress })`, and `publicationToken()`.
- `promoteRunBatch()` returns `published`, `unchanged`, or `already-published`. It verifies sealed ownership/revision, requires each eligible row to exactly match the staged numeric/provenance record, commits accepted rows, final progress, staging/batch cleanup and publication token atomically, and rejects stale or out-of-batch rows. Permissions/source checks are intentionally external to the cache.
- During phase 3, removed the unused legacy direct-publish `checkpointPair()` / `finishRun()` API after auditing production callers (none remained after phase 2 migration). Test writers use ordinary validated cache `upsert()` or progress methods; run checkpoint writes must use staged APIs. This is an internal cache interface compatibility break, with no production caller migration outstanding.
- Purge and acquisition paths remove affected staged records, and stage removal advances the revision fence so a captured validator snapshot cannot promote across that destructive mutation. `reset()` clears staging and batch ownership. Publication token updates are transactional with published writes/purge/reset/promotion.
- Added `jev-pair-cache-staging.test.ts` for isolation/revision invariance, ownership/sealing, promotion rollback, idempotency/reopen, no-op and exact-row checks, purge/reset/transfer fencing, and external SQLite mutation invalidation.

## Phase 4 implementation record (in progress)

- Cache admission now retains only complete snapshots with a current `unified-v2` semantic read proof and an available, stable storage authority identity. This applies irrespective of whether redundancy output is currently enabled; legacy `verified`, `not-used`, custom, unavailable, or degraded results are not retained. Ordinary response body reuse occurs only after refreshed authority, source vector, time, and proof checks; no scoring/pair scan or body serialization is performed on a validated hit.
- Storage authority reads current bytes for exactly six files (collection, tournament, prediction settings, redundancy settings, niche settings, shelf config), bracketed by stable file metadata checks. SHA-256 identities detect same-revision byte replacement. A changed file invalidates its decoded source cache and marks the source vector unavailable until current files are reloaded; established missing files fence the vector and cannot be silently initialized again. Cache authority-read errors are treated as no-store, and complete production builds are rejected if the available storage authority cannot be established.
- Unified and collection snapshot capture now rehydrate an unavailable source vector before coherent assembly. This permits a valid external same-revision edit to be reread while preserving fail-closed behavior for missing/unreadable files; vector revisions remain the source mutation fence rather than an identity substitute.
- `cs2` validators are opaque hashes over refreshed six-source content identity, semantic source-vector identity, next time transition, unified-v2 proof, and the exact serialized public body. Staging/progress does not alter the published proof or validator; terminal promotion changes the result only when published evidence changes. Reservation flights capture source identity/vector and stale flights cannot be joined across changed authority.
- Added real SQLite + unified-scoring integration evidence: first 200 followed by 304 with one build/serialization; an external shelf-config same-revision content edit forces a fresh 200 without a revision change; run staging keeps the refreshed validator at 304 with no extra build/serialization; promotion makes the old validator return a changed 200 and updated score. Added direct storage tests for same-revision edits across all six sources and established shelf-config deletion without reinitialization.
- Corrected fixture expectations where old custom/no-authority snapshot builders were incorrectly treated as cacheable. Those paths now assert `no-store`; degraded-source recovery remains successful but does not produce an ETag absent complete reusable V2 proof. The queued degraded-flight test remains focused on a fresh complete response and bounded rebuild count rather than asserting that proofless custom readers are retained.
- A direct source-read failure is treated as unavailable authority; it cannot authorize a complete retained result. Established-file deletion now explicitly invalidates the source vector and decoded source cache before loaders run, preventing a cached settings value or silent reinitialization from masking disappearance. Content-change comparison is not conditional on unrelated change-token movement, closing the mixed internal/external edit window.
- A mock build initially exposed that the proofless no-store result incorrectly recorded semantic mode as enabled and retried against a disabled mode. The completed build now records the actual captured semantic mode. Test counts for a caller racing a changed flight are bounded because both the original and queued reader may independently retry; neither can accept the stale flight.
